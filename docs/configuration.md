# Configuration

The API reads its settings from layers, each one overriding the previous:

1. `appsettings.json`: defaults that are safe everywhere;
2. `appsettings.{Environment}.json`: `Development` only in this repository;
3. user secrets, in `Development` only (`dotnet user-secrets`, id `sample-api-local-development`);
4. environment variables, with `__` between sections (`Database__ConnectionString`);
5. command-line arguments;
6. one file per key in the directory `Secrets:Path` (default `/var/run/secrets/sample-api`), where the chart
   mounts a Kubernetes Secret. The file `Database__ConnectionString` sets `Database:ConnectionString`.

Secrets come from the last layer only, or from user secrets on a laptop. None is in an `appsettings` file, in
the chart's values, or anywhere in this repository. The chart refers to Secrets by name. In previews the
operator generates them, and in production they come from wherever the cluster gets secrets (External
Secrets Operator, a CSI driver, sealed secrets).

Every section is validated when the process starts (`ValidateOnStart`). A missing or invalid value stops the
API before it accepts traffic, with the key in the message:

```text
Microsoft.Extensions.Options.OptionsValidationException: Database:ConnectionString is required. Provide it
through the Database__ConnectionString environment variable or the mounted secret file.
```

In Kubernetes, that failure keeps the new pod unready, so a rolling update or a canary stops without taking
traffic. The reasoning is in [ADR 0006](adr/0006-configuration-layers-and-validation.md).

| Key | Default | Rules | Notes |
|-----|---------|-------|-------|
| `Database:ConnectionString` | none | required | **Secret.** Npgsql connection string |
| `Database:CommandTimeoutSeconds` | `30` | 1 to 300 | |
| `Database:MaxRetryCount` | `3` | 0 to 10 | Retries on transient PostgreSQL errors |
| `Authentication:Jwt:Issuer` | `preview-platform` | required | |
| `Authentication:Jwt:Audience` | `sample-api` | required | |
| `Authentication:Jwt:Authority` | none | URL | OpenID Connect discovery: production mode |
| `Authentication:Jwt:SigningKey` | none | 32 characters or more | **Secret.** Shared HMAC key: local and previews |
| `RateLimiting:PermitLimit` | `100` | 1 to 100,000 | Token bucket per user, or per IP when anonymous |
| `RateLimiting:Window` | `00:00:10` | 1 s to 1 h | |
| `Idempotency:Retention` | `1.00:00:00` | 5 min to 7 days | How long an `Idempotency-Key` can be replayed |
| `Idempotency:PurgeInterval` | `01:00:00` | 10 s to 1 day | |
| `DataRetention:Enabled` | `true` | | `false` logs a warning at every start |
| `DataRetention:FreeTextRetention` | `180.00:00:00` | 1 day to 10 years, shorter than the next one | See [data protection](data-protection.md) |
| `DataRetention:RequestRetention` | `1825.00:00:00` | 30 days to 10 years | |
| `DataRetention:Interval` | `06:00:00` | 1 min to 7 days | |
| `Features:AutoApproveSickLeave` | `false` | | Sick leave approved on submission |

| `HolidayCalendar:BaseAddress` | none | URL | Any API serving `GET {base}/PublicHolidays/{year}/{country}` |
| `HolidayCalendar:CountryCode` | `FR` | ISO 3166-1 alpha-2 | |

| `HolidayCalendar:TotalTimeout` | `00:00:08` | 500 ms to 1 min, above the attempt timeout | Retries included |
| `HolidayCalendar:MaxRetryAttempts` | `3` | 0 to 5 | |

| `Telemetry:PrometheusEndpoint` | `true` | | Serves `/metrics` for debugging without a collector |

| `Secrets:Path` | `/var/run/secrets/sample-api` | | Directory of the key-per-file layer |

Telemetry export uses the standard OpenTelemetry variables, read by the SDK itself:
`OTEL_EXPORTER_OTLP_ENDPOINT` (export is off when unset), `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` and
`OTEL_METRIC_EXPORT_INTERVAL`.

## By environment

| | Local (`devctl up`) | Pull request preview | Production (`ci/production-values.yaml`) |
|-|---------------------|----------------------|------------------------------------------|
| `ASPNETCORE_ENVIRONMENT` | `Preview` | `Preview` | `Production` |
| Database | PostgreSQL in the namespace, credentials generated by the operator | same | external, Secret provided by the platform |
| JWT | shared key generated per environment | same | OpenID Connect authority |
| Rate limit | 2000 per 10 s (load tests run as two accounts) | same | 100 per 10 s |
| Data | synthetic seed | synthetic or pseudonymised | real |
| Fault injection | allowed | allowed | refused by the API and by the chart |
| Telemetry | to the collector in `observability` | same | same |

## Operator settings

Set in `deploy/operator/kustomization.yaml` (ConfigMap `preview-operator-config`). `devctl up` overrides the
image references and the public port for the local cluster.

| Key | Default | Notes |
|-----|---------|-------|
| `Operator__PreviewDomain` | `preview.localtest.me` | Previews are served at `pr-<n>.<domain>` |
| `Operator__UrlScheme`, `Operator__PublicPort` | `http`, none | Used to build `status.url` |
| `Operator__MaxTtl` | `72h` | Longer TTLs are capped |
| `Operator__DeployerImage`, `Operator__SeederImage` | GHCR images | Helm-with-chart image and data seeder |
| `Operator__PostgresImage` | `postgres:17-alpine` by digest | |
| `Operator__ImagePullPolicy` | `IfNotPresent` | For the platform's images only. CI sets `Never` because it loads them into kind; PostgreSQL is always pulled when missing |
| `Operator__QuotaCpu`, `Operator__QuotaMemory` | `2`, `3Gi` | ResourceQuota of each preview |
| `Operator__CollectorEndpoint`, `Operator__CollectorNamespace` | collector in `observability` | Empty endpoint: no export |
| `Operator__Workers` | `2` | Previews reconciled in parallel |

## Running the API outside Kubernetes

`.env.example` lists what the container needs. Copy it to `.env` (git-ignored), fill in the connection string
and a signing key (`openssl rand -base64 48`), then:

```sh
docker run --env-file .env -p 8080:8080 ghcr.io/remi-maigrot/sample-api:<sha>
```
